# План разработки топового криптокошелька

## 1. Видение и цели продукта

**Продукт:** некастодиальный мультичейн-криптокошелёк (mobile-first + браузерное расширение), сочетающий безопасность уровня hardware-решений с UX уровня необанков.

**Ключевые цели:**
- Пользователь полностью контролирует свои ключи (non-custodial).
- Порог входа для новичка — не более 2 минут от установки до первой транзакции.
- Безопасность, подтверждённая независимыми аудитами, — главное конкурентное преимущество.
- Поддержка основных экосистем: Bitcoin, Ethereum + EVM-сети (Arbitrum, Optimism, Base, Polygon, BNB Chain), Solana, TON. Расширяемая архитектура для добавления новых сетей.

**Конкуренты и позиционирование:** MetaMask (слабый UX для новичков, только EVM), Trust Wallet (широкий охват, но слабая прозрачность), Phantom (отличный UX, но узкая мультичейновость), Rabby (безопасность транзакций). Наша ниша — «безопасный по умолчанию» кошелёк с человеческим языком подтверждения транзакций и восстановлением без seed-фразы.

## 2. Ключевые фичи

### MVP (обязательное ядро)
- Создание/импорт кошелька: BIP-39/BIP-44 (HD-кошельки), импорт по seed-фразе и приватному ключу.
- Отправка/получение: нативные монеты и токены (ERC-20/721/1155, SPL, Jettons), QR-коды, адресная книга.
- Портфолио: балансы, история транзакций, цены и P&L в фиате.
- Безопасность транзакций: симуляция транзакции перед подписью, расшифровка calldata на человеческий язык, предупреждения о рисках (drainer-паттерны, бесконечные approve, новые адреса).
- WalletConnect v2 и injected provider (EIP-1193, EIP-6963) для dApp.
- Биометрия + PIN, шифрование хранилища ключей (Secure Enclave / Android Keystore / StrongBox).

### Фаза 2 (дифференциация)
- Восстановление без seed-фразы: MPC (2-of-3: устройство + облачный шард + резервный шард) или смарт-контрактные кошельки (ERC-4337, social recovery, passkeys).
- Встроенный своп (агрегатор: 0x/1inch/Jupiter) и мост между сетями с прозрачными комиссиями.
- Покупка/продажа за фиат (on/off-ramp: провайдеры типа MoonPay/Ramp с fallback).
- Стейкинг (ETH LST, SOL, TON) прямо из кошелька.
- Поддержка hardware-кошельков (Ledger, Trezor) как источника подписи.
- Gas abstraction: оплата газа токенами, спонсируемые транзакции (paymaster).

### Фаза 3 (рост и удержание)
- NFT-галерея и управление, поддержка ENS/SNS/имён.
- Мультиаккаунты, watch-only адреса, семейные/командные кошельки (мультисиг).
- Уведомления о входящих транзакциях и активности подписок/approve.
- DeFi-дашборд: позиции в протоколах, health factor, автоалерты.
- Desktop-приложение и синхронизация между устройствами (E2E-шифрование).

## 3. Архитектура

### Общая схема
```
┌─────────────────────────────────────────────────┐
│  Клиенты: iOS / Android / Browser Extension      │
│  ├─ UI-слой (React Native / React)               │
│  ├─ Core SDK (Rust → FFI/WASM): ключи, подпись,  │
│  │   деривация, шифрование — единая кодовая база │
│  └─ Secure Storage (Enclave/Keystore/encrypted)  │
└───────────────┬─────────────────────────────────┘
                │ только подписанные транзакции и запросы данных
┌───────────────▼─────────────────────────────────┐
│  Backend (без доступа к ключам!)                 │
│  ├─ Индексация: балансы, история, цены, NFT      │
│  ├─ Симуляция транзакций + risk engine           │
│  ├─ Нотификации, фичефлаги, A/B                  │
│  └─ Шлюзы к RPC-нодам (свои + Alchemy/QuickNode) │
└─────────────────────────────────────────────────┘
```

### Ключевые решения
- **Core на Rust:** криптография, деривация ключей, сборка и подпись транзакций — одна проверенная библиотека для всех платформ (через UniFFI для мобильных, WASM для расширения). Никакой криптографии «самописом» — только аудированные примитивы (libsecp256k1, ed25519-dalek, BIP-39 референсные реализации).
- **Ключи никогда не покидают устройство.** Бэкенд — только чтение данных блокчейна и вспомогательные сервисы.
- **Модуль сети как плагин:** единый интерфейс `ChainAdapter` (деривация адреса, сборка tx, оценка комиссии, broadcast, парсинг истории) — добавление новой сети не трогает ядро.
- **Инфраструктура данных:** собственный индексатор для топ-сетей + сторонние API как fallback; кэширование цен; никаких запросов с клиента напрямую к третьим сторонам с утечкой IP/адресов (приватность через собственный прокси).

## 4. Безопасность (сквозной приоритет)

- **Модель угроз** до начала разработки: компрометация устройства, фишинг, supply-chain-атаки на зависимости, вредоносные dApp, инсайдер.
- **Хранение ключей:** шифрование AES-256-GCM, ключ шифрования в Secure Enclave/StrongBox, Argon2id для парольной деривации; опционально MPC-шардинг.
- **Подпись:** экран подтверждения показывает реальный эффект транзакции (симуляция), а не сырой hex; anti-blind-signing.
- **Защита цепочки поставок:** lockfile-пиннинг зависимостей, воспроизводимые сборки, подпись релизов, SLSA-уровень для CI.
- **Процессы:** обязательное код-ревью 2 инженерами для core, статический анализ (Semgrep, cargo-audit), фаззинг парсеров транзакций, bug bounty (Immunefi) с запуска, минимум 2 независимых аудита (например, Trail of Bits + Cure53) перед публичным релизом и после каждого крупного изменения core.
- **Открытость:** open-source ядра и клиентов — стандарт доверия в индустрии.

## 5. Технологический стек

| Слой | Технологии |
|---|---|
| Core | Rust (криптография, транзакции), UniFFI, WASM |
| Mobile | React Native (или Kotlin/Swift нативно, если приоритет — платформенная глубина) |
| Extension | React + TypeScript, Manifest V3 |
| Backend | Rust/Go микросервисы, PostgreSQL, ClickHouse (история), Redis, Kafka |
| Инфраструктура | Kubernetes, Terraform, собственные full-ноды + Alchemy/QuickNode fallback |
| Наблюдаемость | Prometheus/Grafana, Sentry (с фильтрацией PII), приватная аналитика (без адресов) |

## 6. Команда

- 1 Tech Lead / архитектор
- 2–3 Rust-инженера (core, криптография)
- 2 мобильных инженера + 1 инженер расширения
- 2 backend-инженера (индексация, инфраструктура)
- 1 security-инженер (full-time с первого дня)
- 1 продакт-дизайнер + 1 PM
- QA-инженер (автоматизация + ручное тестирование на устройствах)

Итого ядро: ~11–13 человек.

## 7. Дорожная карта

### Этап 0 — Фундамент (месяцы 1–2)
- Модель угроз, выбор архитектуры ключей (классический HD vs MPC vs 4337) — ключевое решение, определяющее всё остальное.
- Прототип Rust-core: генерация/импорт, деривация, подпись для ETH + BTC.
- Дизайн-система, UX-исследования (5–10 интервью с целевыми пользователями).
- CI/CD, инфраструктура, стандарты безопасной разработки.

### Этап 1 — MVP (месяцы 3–6)
- Мобильный кошелёк: создание/импорт, отправка/получение, портфолио для ETH + 2–3 EVM-сетей и BTC.
- Индексатор балансов и истории, ценовой сервис.
- Симуляция транзакций и базовый risk engine.
- WalletConnect. Внутреннее тестирование + закрытая бета (100–500 пользователей).
- Первый внешний аудит core.

### Этап 2 — Публичный запуск (месяцы 7–10)
- Solana + TON, браузерное расширение.
- Своп, on-ramp, стейкинг ETH/SOL.
- Второй аудит (клиенты + бэкенд), запуск bug bounty.
- Запуск в App Store / Google Play / Chrome Web Store; маркетинг: партнёрства с dApp, реферальная программа.
- Цель: 50–100 тыс. установок, retention D30 > 25%.

### Этап 3 — Дифференциация (месяцы 11–16)
- Восстановление без seed-фразы (MPC/4337 + passkeys) — публично.
- Hardware-кошельки, gas abstraction, NFT, уведомления.
- Desktop + синхронизация.
- Цель: 500 тыс.+ пользователей, положительная юнит-экономика на своп-комиссиях.

## 8. Монетизация

- Комиссия на своп/мост (0.3–0.85%, прозрачно показана).
- Спред/комиссия on-ramp партнёров.
- Комиссия на стейкинг (10–15% от reward, ниже кастодиальных бирж).
- Принципиально без: продажи данных пользователей, скрытых спредов, платного вывода собственных средств.

## 9. Комплаенс и юридика

- Юрисдикция: выбрать с ясным регулированием некастодиальных кошельков (ЕС/MiCA — некастодиальный софт в основном вне периметра, но on/off-ramp — через лицензированных партнёров).
- KYC не требуется для базовых функций (ключи у пользователя); KYC on-ramp — на стороне провайдера.
- Санкционный скрининг на уровне интеграций (своп/ramp-партнёры), политика конфиденциальности, GDPR.
- Юридическая проверка перед каждым новым рынком и перед добавлением yield-продуктов (риск квалификации как securities).

## 11. Главные риски

| Риск | Митигация |
|---|---|
| Уязвимость в core → потеря средств | Rust, аудиты, фаззинг, bug bounty, поэтапный rollout |
| Фишинг/дрейнеры бьют по репутации | Risk engine, симуляция, обучение в onboarding |
| Зависимость от сторонних RPC/API | Собственные ноды + мультипровайдерный fallback |
| Регуляторные изменения | Модульность фич по юрисдикциям, юр. мониторинг |
| Медвежий рынок → падение активности | Низкий burn rate ядра, фокус на retention, а не на хайп-фичи |
| Демпинг конкурентов | Дифференциация на безопасности и recovery, а не на комиссиях |
